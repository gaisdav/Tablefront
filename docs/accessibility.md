# Accessibility and performance checks

What was checked, how, and what was changed because of it. Re-run the commands when the design tokens or the page structure change.

## Accessibility

| Area                       | How it was checked                                                                                                                                                                       | Result                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Heading order              | Every page walked in Chrome, headings listed in document order                                                                                                                           | One `h1` per page; nothing skips a level (the menu is `h1` then dish `h2`s, My orders `h1`, `h2` sections, `h3` orders). Dialogs have their own `h2`.                                                                                                                                                                                                                                                                                   |
| Names and labels           | The same walk: inputs with no label, buttons and links with no name, images with no `alt`                                                                                                | None. Dish photos are decorative (`alt=""`: the name sits right beside them); icon-only buttons have an `aria-label`.                                                                                                                                                                                                                                                                                                                   |
| Landmarks                  | One `main` per page, a labelled `nav`, skip link as the first Tab stop                                                                                                                   | As intended.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Focus after a route change | New: on a change of path, focus moves to the new page's `h1` (`src/router/accessibility.ts`); the tab title names the page. A change of query only (filters, details) leaves focus alone | Works for keyboard and screen readers; covered by tests and checked in Chrome. The very first page load is left alone.                                                                                                                                                                                                                                                                                                                  |
| Contrast                   | WCAG 2.x ratios computed for every text/background pair of the tokens, in both themes                                                                                                    | All text pairs pass 4.5:1 (the lowest is 4.57). **Found and fixed:** the edge of inputs, selects, outlined buttons, the quantity stepper and the switch track used `--color-border-strong` (1.7:1 light, 1.9:1 dark). Controls now use a new `--color-control-border`, at least 3:1 (WCAG 1.4.11) in both themes; `--color-border-strong` itself is unchanged and stays for decoration (cards, the order stepper, dashed empty states). |
| Colour is not the only cue | Statuses carry a text label, errors an icon or message, the selected chip a different fill and native radio checked state                                                                | As intended.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Reduced motion             | `prefers-reduced-motion` rule in `base.css` shortens every animation and transition; the spinner stays a spinner                                                                         | As intended.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Touch targets              | Controls are at least 44 px (`--tap-size`)                                                                                                                                               | By construction (shared tokens and base components); not measured one by one. The Dev tools button is the same.                                                                                                                                                                                                                                                                                                                         |
| Announcements              | Live regions: cart count, toasts, list counts, order status, **offline banner** (an always-present `role="status"` whose content changes)                                                | As intended; each has a test.                                                                                                                                                                                                                                                                                                                                                                                                           |

Not done: a pass with a real screen reader (VoiceOver/NVDA). The checks above are structural and keyboard-based.

## Performance

Gzipped sizes from a production build (`pnpm build`, mock API not included):

| Chunk                           | Size     |
| ------------------------------- | -------- |
| Entry (Vue, router, Pinia, app) | 58.8 kB  |
| Menu page                       | +6.5 kB  |
| Checkout                        | +4.3 kB  |
| My orders                       | +6.3 kB  |
| Order tracking                  | +6.2 kB  |
| Not found                       | +0.3 kB  |
| Admin login                     | +1.6 kB  |
| Admin layout                    | +2.2 kB  |
| Admin orders                    | +10.0 kB |
| Admin menu                      | +10.1 kB |

- **Route splitting.** Every page and the admin layout is its own chunk; a guest never downloads admin code (checked in the build output).
- **The mock API is not in a real production build** (and neither is the Dev tools panel). The demo build (`VITE_ENABLE_MOCKS=true`) adds about 155 kB gzipped (MSW, the fixtures and the panel), loaded before the app mounts.
- **Images** are `loading="lazy"` with `decoding="async"` and a fixed `width`/`height`, so the space is reserved.
- **Layout shift**, measured in Chrome with a `layout-shift` observer on every page: the only shifts were on the menu page. The category chips changed height by 4 px when they arrived (the skeleton lacked their bottom padding), and the footer, visible under a short skeleton, was pushed out of view by the long list (up to 0.096, just under the "good" limit of 0.1). Both fixed: the chips' skeleton has the same padding, and the dish skeletons have the proportions of a real card (12 of them), so the footer is already below the fold. The menu now measures 0 at 375, 1200, 1440 and 1920 px wide. A window taller than the placeholder list would still see the footer move; that is what any content-driven page does.
- **The offline banner floats** (`position: fixed`, above the Dev tools button's space) instead of pushing the page down, so nothing moves when the connection drops (page height measured before and after).
