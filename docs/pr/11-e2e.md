# PR 11 — End-to-end tests

## What this adds

- **Playwright** (new dev dependency `@playwright/test`, approved in the spec) running real Chromium against the production build of the demo, with the mock API on. `pnpm test:e2e` builds, serves and runs everything in about a minute; `pnpm test:e2e:ui` opens the interactive runner.
- **31 tests in seven files** (`e2e/*.e2e.ts`):
  - `menu`: dishes, category and search filters in the URL, a shared link surviving a reload, a failed load with Retry, skeletons on a slow network.
  - `cart`: the card stepper, the drawer (quantities, removal, empty), Escape returning focus to the cart button, the cart surviving a reload.
  - `checkout`: validation and focus on the first problem, delivery needing an address, a server failure keeping the typed data and the cart and a retry succeeding, tracking, and the order page following the status the kitchen sets from another tab.
  - `my-orders`: no link and an empty page at first, the list with status and a link to tracking, surviving a reload.
  - `admin`: sign-in with return to the requested page, wrong credentials, sign-out, a status change, **the rollback with a reason when the server refuses (forced through Dev tools)**, an unreachable board, and creating, editing and deleting a dish, a dish switched off disappearing from the guest menu, and the unsaved-form question.
  - `offline`: the browser going offline (real `offline` event) and the Dev tools switch, and an order that fails to send keeping the form and going through later.
  - `keyboard`: a whole order from the first Tab to the tracking page without a mouse, with focus visible and moving to each new page's heading; the skip link; a dialog keeping Tab inside.
- **CI**: a separate `e2e` job (Chromium installed, suite run, traces and screenshots uploaded as an artifact on failure).
- Type-checked and linted like the rest (`tsconfig.e2e.json`); Vitest is told to run only `src/**/*.spec.ts`, so the two runners never pick up each other's files.

## Decisions worth a look

- **Against the production build, not the dev server**: it is what is deployed, and it proves the flag that keeps the mock API in the demo build works.
- **Deterministic by construction.** No fixed sleeps anywhere: every wait is for something to appear (Playwright's auto-waiting and web-first assertions). Each test gets an empty browser, so no data leaks between tests, and starts with simulated latency off through the Dev tools panel, which makes the suite fast and removes timing from the picture. A test that wants a slow, failing or offline network asks for it, with the panel. Retries are off: a flaky test is a bug.
- **The suite fails on any console error, warning or uncaught exception** (the browser's own note about a request that a test deliberately failed is ignored), so a test run also checks "no console noise".
- **Staff and guest are two tabs of one browser** in the order-tracking test: the demo database is shared across tabs, which is also how the multi-tab sync is exercised end to end.
- **Waiting for the page to be settled before forcing a failure.** The first version of two tests forced errors while a request was still in flight, and the in-flight request took the failure. The helpers (`openMenu`) wait for everything on screen first; this was found by running every test five times in a row, which is how the suite was checked for flakiness (155 of 155 passed, also with two workers as in CI).

## Not done, on purpose

- **Chromium only.** Firefox and WebKit would triple the CI time for a demo with no browser-specific code; adding them is one line in the config.
- **No visual-regression screenshots**: they are kept on failure for debugging, not compared.
- **No test of the Docker image in the browser**: the image has its own check in CI (`scripts/check-image.sh`).

## How it was checked

- `format:check`, `lint`, `typecheck`, `test` (the unit tests, unchanged) and `build` pass.
- The suite passes on a clean run, five times over (`--repeat-each=5`, 155 runs) and with two workers.
- The tests fail when what they protect is broken: with the focus move on navigation removed, the keyboard journey fails.
